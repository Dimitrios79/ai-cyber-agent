What we test

The risks traditional security testing misses

Web application firewalls and classic pentests look for SQL injection and XSS. LLM applications fail in different ways.

LLM01

Prompt injection

Direct and indirect attacks — including instructions hidden in documents, emails or web pages your system reads.

LLM02 · LLM07

Data & system prompt leakage

Can a user extract customer data, internal documents, API keys or your system instructions?

LLM06

Excessive agency

Agents with tools: can they be tricked into sending emails, changing records or calling APIs they shouldn't?

LLM08

RAG & retrieval weaknesses

Access-control gaps in your vector store and poisoned content that changes what the model says.

LLM05

Unsafe output handling

Model output passed to browsers, shells or databases without validation — where LLM bugs become classic bugs.

LLM10

Cost & resource abuse

Inputs that drive runaway token usage, loops or denial-of-wallet against your API budget.

FINDING F-03 · LLM01High

Indirect prompt injection via uploaded PDF

Description
Hidden text in an uploaded document overrides the assistant's instructions when the document is summarised.
Impact
An attacker can make the assistant reveal other customers' ticket history in its reply.
Recommendation
Treat retrieved content as untrusted data, enforce per-user access checks in retrieval, not in the prompt.
